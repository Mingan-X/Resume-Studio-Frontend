# 产品与界面规范

本文定义页面内容、展示规则和视觉约定。业务含义以后端[业务需求](https://github.com/Mingan-X/Resume-Studio-Backend/blob/master/docs/requirements.md)为准；页面路由见[架构 §6](architecture.md#6-路由)。

## 1. 用户与核心流程

首版用户是求职者本人：

1. 上传简历（PDF/DOCX），查看解析结果。
2. 准备岗位：新建或导入JD，确认结构化要求后发布。
3. 选择简历版本和岗位范围，发起分析。
4. 查看任务进度。
5. 阅读报告：六维画像、推荐岗位、待核实岗位、差距与证据；按需调整权重重算。

## 2. 必须遵守的展示规则

这些规则来自后端的证据与评分语义，违反任何一条都视为缺陷。

1. **前端不计算分数。** 分数、贡献、coverage、upperBound、资格和排名全部使用后端返回值，原样显示。
2. **unknown与unmet分开展示。** “证据不足”（UNKNOWN）用中性色和文字标签；“不满足”（UNMET）用警示色和文字标签。两者都必须有文字，不能只靠颜色区分。
3. **证据不足的维度不画成0分。** 六维雷达图中unknown维度不连线到0，在图旁用文字列出“证据不足：X维度”，并在等价表格中显示“—（证据不足）”。
4. **PARTIAL报告必须醒目说明。** 报告顶部显示横幅：已评估候选数 / 计划候选数、未完成数量与原因，并写明“排名仅基于已评估岗位”。
5. **推荐不足10条时说明原因。** 显示后端给出的原因，不补占位卡片。
6. **待核实岗位单独列出。** 硬条件无法验证的岗位放在“待核实”区域，不混入推荐列表，不显示为0分。
7. **分数同时显示覆盖率与上界。** 例如“62.50分 · 覆盖率75% · 上界87.50”，并提供说明浮层。
8. **证据可展开核对。** 每条判断可展开显示简历原文quote及位置（PDF页码或DOCX段落编号，以后端提供的为准）；quote按纯文本显示。
9. **不伪造进度。** 只显示后端给出的阶段名与计数；总量未知时只显示阶段；报告未提交前不显示100%；不显示“模型正在思考”类文案。
10. **重算生成新版本。** 调权重算后跳转到新报告revision，原报告在历史中保留，界面标明新报告来源于哪一份。

## 3. 页面内容

### 3.1 简历（S2.1）

- 列表：文件名（用户上传时的显示名）、上传时间、版本号、解析状态、操作。
- 上传：拖拽或选择文件；显示支持格式、大小上限；上传进度与取消；失败原因显示在上传区域内。扫描PDF、加密文件等明确提示“不支持”。
- 详情：版本信息、解析出的文本块及位置（PDF页码或DOCX段落，以后端提供的为准）、解析警告列表。结构化信息（教育、工作、项目、技能）由分析产出，在报告页展示（见§3.5）。

### 3.2 岗位（S2.2）

- 列表：岗位名、版本、发布状态、索引状态（待索引 / 索引中 / 可用 / 失败）。
- 新建：粘贴或导入JD正文 → 查看模型抽取的结构化要求 → 逐条确认或修改硬门槛与权重 → 发布。
- 发布前提示：发布后的版本不可修改，修改会生成新版本。
- 索引失败的岗位标明“未参与召回”。

### 3.3 发起分析（S2.4）

- 选择简历版本与岗位范围；显示将使用的版本信息。
- 提交后跳转任务页。提交按钮在请求期间禁用。

### 3.4 任务进度（S1.4起）

- 状态标签、当前阶段、计数（如“已匹配 8 / 20 个岗位”）、当前尝试次数、下次重试时间。
- `RETRY_WAIT` 显示“等待重试”与时间；`FAILED` 显示安全错误信息与requestId；`CANCELLED` 显示已取消。
- 运行中提供“取消”按钮，点击后显示“取消请求已提交”，最终状态以后端为准。
- 成功或部分成功后显示“查看报告”。

### 3.5 报告（S3.1）

页面分区：

1. 概要：分析时间、简历版本、岗位范围、Rubric与评分规则版本、PARTIAL横幅。
2. 结构化简历：教育、工作、项目、技能，每项可跳转到来源文本块；不存在的字段显示“未识别”，不显示空白也不编造。
3. 六维画像：雷达图 + 等价表格；每维显示等级或“证据不足”、判断理由、证据展开。
4. 推荐岗位（最多10条）：排名、岗位、分数/覆盖率/上界、主要差距；展开显示逐条要求的verdict、贡献与证据。
5. 待核实岗位：列出无法验证的硬条件。
6. 不符合硬条件的岗位：可折叠，说明哪条硬条件不满足。
7. 调权重算：调整各维度权重（后端校验非负、总和大于0），提交后生成新报告。
8. 报告历史：同一分析的各个revision。

## 4. 通用状态

| 状态 | 规则 |
|---|---|
| 加载 | 首次加载用骨架屏；刷新数据时保留旧内容并显示轻量加载指示 |
| 空 | 说明为什么为空以及下一步操作，例如“还没有简历，上传一份开始分析” |
| 错误 | 显示后端message、requestId（可复制）与可用的重试操作 |
| 无权或不存在 | 统一显示“不存在或无权访问” |
| 部分可用 | 已有数据正常显示，缺失部分标明原因 |

## 5. 视觉与交互

- 使用Element Plus默认主题，通过CSS变量覆盖品牌色；颜色、间距、圆角只在 `src/app/styles/tokens.css` 定义，组件中不写死颜色值。
- 语义色：成功/满足=绿色系，部分满足=琥珀色系，不满足=红色系，证据不足=灰蓝色系。每种都配文字或图标。
- 数字使用等宽数字（`font-variant-numeric: tabular-nums`），分数固定显示两位小数（取后端值）。
- 时间显示为用户本地时区，格式 `YYYY-MM-DD HH:mm`；悬停显示完整ISO时间。
- 危险操作（删除、取消任务、发布岗位）使用二次确认，确认文案写明后果。
- 表单错误显示在字段下方；提交失败不清空用户输入。

## 6. 文案

- 使用简洁中文，直接说明状态和下一步。
- 不出现“AI认为”“模型觉得”等拟人表述；判断理由引用后端返回的解释文本。
- 不显示内部字段名、错误堆栈或英文错误码；错误码只用于开发者，可放在可展开的“详情”中。

## 7. 可访问性

- 所有交互元素可用键盘到达并有可见焦点。
- 图标按钮提供 `aria-label`。
- 图表提供等价表格；颜色对比度满足WCAG 2.2 AA。
- 状态变化（任务完成、上传失败）通过 `aria-live` 区域告知读屏用户。
