# 开发计划

本文是前端阶段划分、任务拆分和验收标准的唯一来源；完成情况记录在[开发进度](progress.md)。后端阶段见[后端开发计划](https://github.com/Mingan-X/Resume-Studio-Backend/blob/master/docs/development-roadmap.md)。未标记为“已完成”的内容都不是已交付能力。

阶段编号用于分支命名（`feature/f1.1-<功能名>`，见[CONTRIBUTING](../CONTRIBUTING.md)）。“依赖后端”列中的阶段完成并合并后，前端对应阶段才能与真实接口联调。

| 阶段 | 名称 | 主要交付 | 依赖后端 | 阻塞决策 | 状态 |
|---|---|---|---|---|---|
| F1.1 | 工程基线 | 脚手架、类型检查、Lint/格式、单元与E2E测试框架、开发代理、健康状态页 | 无（`/health` 已实现） | — | 未开始 |
| F1.2 | 应用骨架与共享层 | 布局、路由、HTTP客户端、错误标准化、全局错误处理、设计变量、404页 | 无 | — | 未开始 |
| F1.3 | 契约接入与任务页 | OpenAPI快照与类型生成、任务进度页与取消 | S1.4（T8、T9） | — | 未开始 |
| F2.1 | 简历 | 上传、列表、版本详情与解析文本块 | S2.1 | — | 未开始 |

| F2.3 | 发起分析 | 选择简历与岗位范围、创建分析任务 | S2.4 | — | 未开始 |
| F2.4 | 报告 | 六维画像、推荐、待核实、差距、证据展开、PARTIAL展示 | S3.1 | — | 未开始 |

状态只使用：未开始、进行中、待联调、待验收、已完成、已搁置。“待联调”表示基于MSW完成、尚未与真实后端验证。状态变化必须同时更新本表和[开发进度](progress.md)。

F1.1与F1.2不依赖后端业务接口，可以立即开始。F2.x可以在后端对应接口的Schema合并进契约后，先基于MSW开发到“待联调”。

## 2. 任务规范

只有当前阶段和后续一到两个阶段拆分到任务级；更后的阶段在开始时按本节模板补充，并经维护者确认。

每个任务写明编号（`<阶段>-T<序号>`）、目标、依赖、产出、验收和检查命令。

任务完成的定义（Definition of Done）：

1. 验收条件全部有对应测试或可复核的运行记录。
2. `pnpm run typecheck`、`pnpm run lint`、`pnpm test`、`pnpm run build` 通过；涉及用户流程时 `pnpm run test:e2e` 通过。
3. 遵守[界面规范](ui-guidelines.md)第2节的展示规则与[编码规范](coding-standards.md)。
4. 依赖变化同步提交锁文件，并更新ADR版本表。
5. 在[开发进度](progress.md)追加记录：完成内容、验证命令与结果、未执行项及原因。

## 3. F1.1 工程基线

| 任务 | 目标 | 依赖 | 产出 | 验收 |
|---|---|---|---|---|
| F1.1-T1 | 项目初始化 | — | `package.json`（engines、精确版本、脚本）、`.npmrc`、`.node-version`、`.gitignore`、`pnpm-lock.yaml`；Vue、Vite、TypeScript、vue-tsc | 安装前按[ADR-0001](decisions/0001-frontend-stack.md#候选版本)重新核对registry版本与peers；冻结安装成功；`pnpm run build` 产出 `dist/`；不忽略peer冲突 |
| F1.1-T2 | 类型检查与Lint | T1 | `tsconfig*.json`（严格选项见编码规范）、ESLint flat config（含 `vue/no-v-html`、依赖方向的 `no-restricted-imports`）、Prettier配置 | `typecheck` 与 `lint`（零警告）通过；故意写入跨feature内部导入或 `v-html` 时Lint报错（用临时文件验证后删除，并在进度中记录） |
| F1.1-T3 | 单元与组件测试框架 | T1 | Vitest、Vue Test Utils、happy-dom、覆盖率配置，示例测试一项 | `pnpm test` 不需要网络与后端；覆盖率报告生成 |
| F1.1-T4 | E2E测试框架 | T1 | Playwright配置、浏览器安装说明、冒烟用例：打开首页 | `pnpm run test:e2e` 在本机通过；浏览器下载目录不提交 |
| F1.1-T5 | 开发代理与健康状态 | T1 | Vite代理 `/api` 与 `/health`；`features/system` 显示后端健康状态（手写类型，注明来源 `src/contracts/http.ts`） | 后端运行时显示状态与environment；后端停止时显示网络错误而不是空白；真实后端冒烟测试通过 |
| F1.1-T6 | 文档与进度 | T1–T5 | README命令、部署文档、ADR版本表（已安装版本）、进度记录 | 文档与实际脚本一致 |

## 4. F1.2 应用骨架与共享层

| 任务 | 目标 | 依赖 | 产出 | 验收 |
|---|---|---|---|---|
| F1.2-T1 | 应用装配与布局 | F1.1 | `app/` 下的创建函数、Vue Query/Pinia/Element Plus安装、主布局（顶栏、侧边导航、内容区）、`tokens.css` | 导航项与[路由表](architecture.md#6-路由)一致，尚未实现的页面显示“功能开发中”且不发请求；键盘可操作导航 |

## 6. 后续阶段交付与验收

| 阶段 | 交付内容 | 验收要求 |
|---|---|---|
| F2.1 简历 | 上传（进度、取消、预检）、列表（游标分页）、版本详情、解析文本块与警告 | 不支持格式与超限文件在上传区域提示；扫描/加密PDF显示明确原因；上传提交带Idempotency-Key且网络重试复用；来源文本块可定位；版本详情不展示结构化字段（后端S2.4起由分析产出） |
| F2.2 岗位 | JD新建与导入、结构化要求逐条确认、硬门槛与权重编辑、发布确认、索引状态 | 发布前二次确认并说明不可修改；权重输入前端预检非负且后端错误按字段显示；索引失败岗位标明“未参与召回” |
| F2.3 发起分析 | 简历版本与岗位范围选择、提交、跳转任务页 | 提交带Idempotency-Key且重试复用；重复点击不产生多个任务；版本信息在提交前可见 |
| F2.4 报告 | 概要、结构化简历（教育/工作/项目/技能）、六维画像（雷达+表格）、推荐列表、待核实、硬条件不符、逐项判断与证据展开、PARTIAL横幅 | 结构化简历的未识别字段显示“未识别”，各项可展开来源文本块；[界面规范](ui-guidelines.md)第2节十条规则全部有测试；含HTML的证据按纯文本显示；刷新与重新打开后内容不变 |
| F2.5 调权重算与历史 | 权重调整表单、重算后跳转新revision、报告历史、SSE进度替换轮询 | 原报告保持不变；新报告标明来源；SSE断线后按 `Last-Event-ID` 补读，失败回退轮询 |
| F3.1 登录与权限 | 登录页、会话失效处理、路由守卫、CSRF头 | 未登录访问跳转登录并在登录后返回原页面；越权资源显示“不存在或无权访问”；前端不保存令牌 |
| F3.2 质量与发布 | 关键流程E2E、WCAG 2.2 AA审查、构建体积分析、安全响应头与CSP实测、部署配置与回滚流程 | 审查与测量结果记录在进度中；CSP放宽项有理由；回滚演练一次 |
